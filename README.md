# zxx｜新手海报设计工作流

把每次做海报的过程固定为：**上传素材 → 提出要求 → 反复修改 → 下载成品**。

这是一个保存说明、提示词和作品的工作目录。不需要安装软件、运行命令或配置本地环境。仓库本身不会生成图片，也不会自动把聊天中的图片保存进来；实际出图需要当前聊天提供相应的图片生成或编辑能力。

## 2. 最简单的使用方法

### 第一步：上传素材

准备一张清晰原图，直接作为附件上传到具备图片编辑能力的聊天中。需要固定 Logo 或参考风格时，一起上传并分别说明用途。

**为什么：**让 AI 看到真实素材，减少对人物、品牌和画面的猜测。只发送仓库链接不代表当前聊天已经读取其中的文件。

本仓库初始化时为公开仓库。人物原图、客户未公开内容可直接用于聊天，不必提交到这里；只把适合公开且有权使用的素材归档进仓库。

### 第二步：提出要求

打开 [第一版模板](prompts/01-first-draft.md)，复制代码框内的文字，填写方括号部分，与素材一起发出。至少明确：图片用途、尺寸、画面文字、必须保留的内容。

**为什么：**一次说清硬性条件，可以减少无效返工。首次练习可直接使用 [完整示例](examples/first-poster.md)。

### 第三步：反复修改

打开 [修改模板](prompts/02-revision.md)。说明以哪张图为基础，每轮集中提出 1～3 项具体修改，并说明已满意的部分。换聊天或版本不明确时，把选中的版本和必要原图重新附上。

**为什么：**“更好看一点”缺少判断标准；“只放大标题、背景简洁一些、保留人脸与文案”更容易检查。图片编辑仍可能改变未要求修改的细节，每轮要对照原图检查。

### 第四步：下载成品

打开 [交付模板](prompts/03-delivery.md)，核对中文、人脸、裁切与实际像素尺寸。通过后，使用聊天界面的下载功能保存图片到电脑。

需要归档时，再手动上传到 `outputs/`。下载和上传是两个动作，聊天结果不会自动进入 GitHub。

**为什么：**保存可下载的原文件和明确版本，方便以后继续改，避免拿错图。

## 3. 默认封面规范

这是一套可修改的示例默认值，每次明确提出的新要求优先。

- 竖屏宽高比写作 **9:16**，目标尺寸 **1080 × 1920 px**，避免“16:9 竖屏”的歧义。
- 居中 **3:4 竖屏安全区**为 **1080 × 1440 px**：从顶部向下 240 px 到 1680 px，标题、人物面部、Logo 和关键信息放在其中并留边距。
- 上下各 240 px 延续自然背景，不放关键信息、不加黑边。该安全区是本工作流的设计约定，发布前仍需查看实际平台的裁切预览。
- 风格默认暖色、简洁、自然；字要清晰，排版可适当错落。
- 人脸保真是验收要求，不是对生成工具的保证；如果必须逐像素保留原脸，应保留原照片层并采用支持局部编辑／分层合成的工具。
- 目标尺寸不等于工具一定能直接输出的尺寸。交付时检查实际文件，必要时明确说明还需要调整。

## 4. 用 GitHub 网页归档即可

- 上传：进入对应目录 → 找到 **Add file / Upload files**（添加文件／上传文件）→ 选择文件 → 填写简短说明 → **Commit changes**（提交更改）。界面标签可能因语言和版本而不同。
- 编辑文字：打开 Markdown 文件 → 点击编辑按钮 → 修改 → 提交更改。
- 下载整个目录骨架：仓库首页 **Code → Download ZIP**；只做图时，也可以仅复制模板，无需下载整个仓库。
- 归档命名参考：`retirement-cover_v01.png`、`retirement-cover_v02.png`、`retirement-cover_final_v03.png`，详见 [成品说明](outputs/README.md)。

## 5. 现在不用安装 Skill

先手动跑通一次流程，再看 [Skill 后续说明](docs/skill-next-steps.md)。本仓库当前没有安装 Skill，没有脚本，也没有自动化任务。
