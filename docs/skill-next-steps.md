# 后续接入 Skill：先把流程用熟

## 当前已经有什么

你已经有素材规则、三段提示词、版本命名和一次完整操作示例。现在直接复制模板就能使用，不需要安装 Skill。

**本仓库当前没有可安装的 Skill，也没有安装任何 Skill。**本文件是后续接入说明，不是 `SKILL.md`，不会因为放在 GitHub 中就自动生效。

## 三件事要分清

| 内容 | 作用 | 不代表什么 |
| --- | --- | --- |
| GitHub 仓库 | 保存说明、素材和作品，记录文件变化 | 不代表聊天已经读取文件 |
| 提示词模板 | 每次复制后，告诉 AI 本次怎么做 | 不代表已安装 Skill |
| 已安装且在当前环境可用的 Skill | 提供可重复使用的任务规则与步骤 | 不会凭空增加图片编辑工具、保证人脸一致或自动保存成品 |

不同 ChatGPT／Codex 使用环境的可用功能和安装入口可能不同。以当时环境提供的技能管理能力为准，不要把“发一个 GitHub 链接”理解为完成安装，也不要假设普通聊天能读取所有仓库内容或调用所有 Skill。

## 什么时候值得整理成 Skill

做过几次后，如果每次都重复同样的安全区、人脸保真、暖色风格和交付检查要求，就可以把这些稳定规则整理成技能。每次变化的标题、活动时间和人物照片继续由你提供。

建议整理这些内容：

| 来源 | 将来写入的规则 |
| --- | --- |
| [仓库 README](../README.md) | 适用任务、默认尺寸、安全区及新要求优先 |
| [素材说明](../assets/README.md) | 读取素材、明确角色、保留原图 |

| [最小示例](../examples/first-poster.md) | 一次真实任务的操作参考 |

## 以后可以直接提出的请求

> 请根据 594730712-boop/zxx 中的 README、提示词模板和完整示例，整理并安装一个“新媒体海报工作流”Skill。先检查当前环境是否支持安装以及图片编辑。保留手动上传素材、提出要求、逐轮修改和下载成品的流程；不引入脚本或自动上传。

届时应由具备相应能力的环境完成：读取当前文件 → 整理规则 → 创建含名称、适用描述和步骤的 `SKILL.md` → 按该环境支持的方式安装 → 用一张真实素材验证。

目前无需自己创建系统文件夹或配置本地路径。将来只把文件放入这个工作流仓库，仍不等于已经安装；必须在实际使用环境确认技能可用。

## 验收一个未来的 Skill

- 能说明当前是否看到了附件，缺少素材时不会假装已读取。
- 能使用当次指定的尺寸、文字和修改范围。
- 能保持“原图 → 草稿版本 → 确认成品”的区分。
- 不会把建议图、预览描述或未生成的文件称为可下载成品。
- 对人脸保真和实际输出尺寸诚实说明能力限制。
- 不会未经要求把照片或成品上传到公开仓库。

Skill 用来减少重复说明；实际出图、格式转换和文件归档仍取决于可用工具与本次授权。
